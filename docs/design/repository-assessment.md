# Splash repository assessment

Evidence baseline for the [Agent Experience proposal](agent-experience.md). Audited tree `9bf9e3654387f7c381737ed89d4c9f1e4713eee5`, initially clean on `master`. Source links below refer to that tree. The November 26 discussion motivated the audit. Its engagement figures play no role in conclusions about demand, performance, or language design.

**Implementation update.** The compiler now shares captured source and typed modules across the CLI. It resolves named calls, checks required source policy coverage and issues an in-process `VerifiedProgram` for source artifacts. Persisted provenance remains proposed. The findings below preserve the pre-kickoff audit baseline. [Architecture decision](../decisions/2026-11-26-analyzed-program-and-verification.md) · [Engineering plan](engineering-plan.md)

## Original intent and direction

The PRD already names human–AI collaboration, agent-legible syntax, explicit contracts, observability, and adapter-first development. It explicitly borrows Go’s simplicity and deployment model, Swift’s optionals and value semantics, and Rust’s enums, pattern matching, and ownership clarity. These are design influences. They confer no current guarantees about ownership, exhaustiveness, or runtime behavior. [PRD philosophy](../../PRD.md#L3) · [language influences](../../PRD.md#L35) · [adapter contracts](../../PRD.md#L127) · [observability](../../PRD.md#L368)

The April positioning memo narrowed the initial market to control-plane programs whose authority must be understood before execution. It already proposed a canonical analyzed-program representation, CLI golden tests, introspection, tighter modules, and better diagnostics. The multi-file pipeline changed in `340fc93`, first-class authority syntax and inspection commands landed in `cb9cee7`, and redline justification metadata followed in `449edf4`. The current GitHub description emphasizes agent-built software. The website still leads with execution safety. AX makes the authoring thesis independently testable and gives the earlier architecture proposals a consumer. [April memo](../superpowers/specs/2026-04-07-splash-language-positioning.md#L290) · [repo description](https://github.com/gosplash/splash) · [published whitepaper](https://gosplash.dev/)

The Phase 1 plan explicitly proposed an effect-checker pass with tests. The later effects plan concentrated on the bitset, call graph, and reachability policies. That history helps explain why the current package structure and docs imply more verification than the implementation supplies. [Phase 1 effect-checker task](../superpowers/plans/2026-04-01-splash-phase1.md#L3351) · [Phase 2 effects plan](../superpowers/plans/2026-04-01-phase2-effects.md#L13)

The shared strengths are signatures that expose intent, explicit module boundaries, a separate static loop, and a graph that can explain the consequences of changes. The tensions are equally concrete. Written effect declarations may increase edits and tokens when authority changes. Flat and qualified imports create competing idioms and disagreements across phases. Hidden approval error lowering simplifies source signatures while making their operational contracts incomplete. An agent-readable security reason is valuable review context and remains author-supplied text.

## Trust model for the initiative

The evidence supports specific checks over compiler-modeled source, declared effects and resolved inputs within the current subset. Future authority claims require agreement between binding, graph edges, policy and lowering. Unsupported indirect or dynamic calls, concurrent callbacks and delegated dispatch require a conservative target set, an explicit trusted boundary or rejection. Native compiler success tests Go’s constraints. It adds no proof of Splash policy or behavior.

A future verified build trusts the Splash verifier and lowering, Go toolchain and immutable inputs, approved boundary declarations and actual adapter implementations, deployment configuration and runtime dispatch. A modeled `Net` label establishes no destination allowlist. A hook called before the body establishes no authenticated approval. Concurrent runtime calls, remote API behavior, configuration swaps and foreign state can each require independent controls. A repository-writing agent can change policies, inputs or build code under its own credentials. A protected CI verifier, trusted baseline, exact source identity and controlled release path are prerequisites for enforcing authority review against that author. ## Validation and performance

Ran on November 26, 2026 local time with Go 1.26.3, darwin/arm64, Darwin 27.0.0, Apple M5 reported by Go’s benchmark harness, default GOMAXPROCS 10. The repository declares Go 1.26.2. The unmodified suite and an uncached coverage run passed. Package-local statement coverage was 63.0% aggregate, 53.2% CLI, 57.8% parser, 75.1% type checker, 66.4% graph, 92.2% safety and 77.5% codegen. These percentages measure executed statements. Safety unit tests directly assemble parser, graph and safety, while CLI tests exercise a handful of cross-file paths. CI runs Ubuntu Go tests and builds compiler binaries for multiple platforms. Locally all 12 tracked example source files passed `check`, the hello example built and printed `Hello, world`, and OpenAI tool export produced a provider envelope. The example check run provides analysis coverage only. The separate CPU sample shows prominent runtime allocation-related work, scheduling and garbage collection edges. Assembly, OS and runtime samples complicate phase attribution, so the profile provides a lead alongside the allocation counts. The Go installation lacked the standalone `go tool pprof` command and the bundled preprocessor provided edge weights. The component timings suggest simple graph construction is a fraction of the end-to-end workload, without isolating a dominant source phase. The first performance investment should measure per-phase CPU and allocations on representative multi-file programs with invalid edits and several agent roots. A single BFS has linear traversal complexity. Repeated safety BFS, AST parsing and input size determine total cost. The current fixture provides no evidence for general linear scaling, latency percentiles in a CLI loop, or Go-equivalent runtime speed.

## Consequences for prioritization

Release blockers for a policy-bearing semantic interface are missing declared-effect enforcement, disagreement on symbol and edge identity, cross-module policy attribution, and divergent checked versus emitted paths. Predictability of calls, assignments, defaults, optionals and unsupported constructs matters immediately to the ordinary-software benchmark. Native acceptance cases should pin down behavior before it is described as a language guarantee. The lab can run typed, small task pilots alongside that work. A database/HTTP ecosystem expansion, full information-flow analysis, foreign linkage and package authority all have separate prerequisites.
